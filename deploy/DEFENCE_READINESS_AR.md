# قائمة الجاهزية قبل المناقشة

ما لم أتحقق منه بنفسي (يحتاج حساباتك): كل البنود المتعلقة بـ Supabase والنشر.

## قبل العرض بيوم
- [ ] مشروع Supabase فعّال (غير موقوف بسبب الخمول).
- [ ] تشغيل `001_init.sql` و`002_seed_demo.sql` و`003_demo_data.sql` تم بنجاح.
- [ ] الخادم المنشور يرد على `/health`.
- [ ] الواجهة المنشورة تفتح، وتسجيل الدخول يعمل من رابط الواجهة (لا خطأ CORS).
- [ ] حساب لكل دور يدخل بنجاح: مدير النظام، مدير الشركة (`manager@aber.local`)، موظف الفرع (`staff@aber.local`)، السائق (`driver@aber.local`).
- [ ] جوال أو كاميرا جاهزة لمسح QR (لم يُجرَّب المسح بالكاميرا فعليًا بعد).
- [ ] نسخة محلية احتياطية تعمل (`npm run dev` في المجلدين) إن تعطل الإنترنت.

## قبل العرض بساعة
- [ ] افتح `/health` لإيقاظ الخادم.
- [ ] افتح الواجهة وسجّل دخول مسبقًا في نافذة لكل دور.

## سيناريو العرض (كامل)
1. عميل: صفحة التتبع العامة برقم شحنة تجريبية (من `003_demo_data.sql`، تُنشأ أرقامها تلقائيًا؛ اقرأها من شاشة الشحنات).
2. موظف الفرع (حلب): إنشاء شحنة جديدة، تظهر نتيجة التسعير ورمز التسليم مرة واحدة، ثم طباعة الملصق.
3. مدير الشركة: إنشاء رحلة وإسناد الشحنة.
4. السائق: فتح الرحلة، مسح التحميل، الانتقال إلى «في الطريق»، مسح الوصول، وإظهار كشف النقص إن وُجد.
5. موظف الوجهة: تسليم الشحنة برمز OTP (للشحنات التجريبية: `123456`).
6. مدير الشركة / موظف الفرع: تقرير الفرع اليومي.
7. مدير النظام: اعتماد شركة جديدة أو إيقافها.

## نقاط لم تكتمل ويجب ذكرها بصدق
- تقرير PDF لكل شحنة غير منفذ (قرار الخط العربي معلق).
- إحصاءات مدير النظام غير موجودة.
- لم يُختبر شيء على قاعدة بيانات حقيقية من جهتي؛ الاختبارات الآلية تستخدم بدائل في الذاكرة.
- تقارير مدير الشركة: التقرير اليومي موجود فقط.
